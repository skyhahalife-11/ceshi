# Suture

AI Gate 配置诊断与一键修复工具。面向不熟悉技术细节的同事：双击打开，
先测网关是否正常，再检查本机客户端配置，发现问题一键修好并验证。

覆盖三个客户端：Claude Code CLI、Codex CLI、DeepSeek Harness。

## 跑起来

```bash
python3 main.py                  # 图形界面
python3 main.py --cli            # 命令行
python3 main.py --cli --no-fix   # 只检测不修改任何文件
```

图形界面会优先用系统自带的 WebView 开一个应用窗口；初始化不成功（主要是 Linux
上没装 WebKitGTK）就退回默认浏览器，界面内容一样。设置 `SUTURE_NO_BROWSER=1`
可以只起服务、不主动拉起浏览器。

## 打包

```bash
./build/build.sh                 # 在当前这台机器上打一个单文件可执行程序
```

六个平台组合需要六台对应系统/架构的机器——PyInstaller 不能跨系统交叉编译，
这是工具本身的限制。`.github/workflows/release.yml` 里是六条并行的构建流水线，
macOS 用 universal2 把两种架构合成一个文件。

## 验收测试

```bash
python3 -m unittest discover -s tests -t .
```

测试不依赖真实网关：`mock_gateway.py` 起一个假网关，可以让它表现成正常、
5xx、限流、鉴权拒绝、跑着跑着开始出错等各种情况，用来触发各条判断分支。
每个用例都用独立的临时 HOME 和项目目录，不会碰到你自己的配置。

## 代码结构

| 位置 | 职责 |
|---|---|
| `suture/profile.py` | 加载网关规则（地址、鉴权、模型路由表），预留了从网关运行时拉取的接口 |
| `suture/harness/` | 三个客户端各一个适配器，把各自的配置结构归一化成同一套字段 |
| `suture/checks.py` | 所有检测项，只认归一化后的结构，与具体客户端无关 |
| `suture/gateway.py` | 出网请求与响应分类 |
| `suture/fixer.py` | 备份、写入、回滚 |
| `suture/engine.py` | 三个阶段的编排，命令行和界面共用 |
| `suture/server.py` | 界面用的本地接口，只监听 127.0.0.1 并带一次性令牌 |
| `suture/ui/index.html` | 界面本身，自包含，不引任何外部资源 |
| `gateway_profile.json` | 网关规则。网关新增模型或调整协议时改这里，不用重新分发二进制 |

设计说明见 `DESIGN.md`，产品侧的判断依据见产品方案文档。

## 几条守住的边界

- **Key 不出本地。** 只用于向网关发请求和写回本机配置；界面、日志、接口返回里
  一律只出现掩码后的形式（前 4 位 + 后 4 位）。
- **网关有问题时不动本地配置。** 阶段一探的是规则里那个已知正确的地址，先确认
  网关本身活着；超时、连不上、限流、5xx 直接停下。鉴权被拒不算网关侧问题——那
  更可能是本地 Key 配错了，正是要抓的场景。
- **修完必须验证，失败要归因。** 写入后用修正后的配置重发真实请求；仍不通就补测
  一次网关：网关这时候也异常，说明是网关的问题，保留修复不回滚；网关正常就说明
  这次修复没解决问题，回滚到备份。
- **只改实际生效的那一层。** Codex 的项目级配置在项目不可信时整层不生效，这种情况
  下不会去写它——写了等于没改。
- **不猜。** 配置文件读不懂就如实报错，不按猜测继续。模型名只在「明显是打字错误」
  （大小写、连字符写法）时自动纠正；如果纠正后的候选本身也是路由表里另一个独立
  型号（比如 `gpt-5.6` 与 `gpt-5.6-sol`），一律不自动改，交给用户确认——那会让人在
  不知情的情况下连到另一个模型，比直接报错更糟。

## 已知限制

- **DeepSeek Harness 的 YAML 用的是自己写的受限读取器。** 标准库没有 YAML 解析器，
  而引擎要保持只依赖标准库。支持嵌套映射、列表、标量、引号、注释；遇到锚点、块标量、
  流式写法、多文档会明确报错而不是猜。写回用户层 `settings.yaml` 时不保留原有注释
  （写前有备份）。
- **协议版本头检测默认关闭。** 网关是否校验 `anthropic-version` 尚未确认，确认后把
  `gateway_profile.json` 里 `protocol_version.check_enabled` 改成 `true` 即可，不用改代码。
- **Codex 的 base_url 是否需要 `/v1` 后缀待实测。** 按 OpenAI 兼容协议的惯例应该要带，
  代码里也是这么处理的，但需要实际连一次 Codex CLI 确认。
- **签名尚未接入。** macOS 不签名 + 不公证的话 Gatekeeper 会直接拦截，非技术用户打不开；
  Windows 会弹 SmartScreen 警告。证书就绪后在构建流水线里补上这两步。
